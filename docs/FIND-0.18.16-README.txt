FIND - version 0.18.16
====================

Find is a native macOS file browser (AppKit, Swift 4.1). No browser, no server, no internet.
Target: the office iMac (macOS 10.13 High Sierra, Xcode 9.4). The same build also runs on the
Intel MacBook Pro (macOS Tahoe).


BUILD IT (on the office iMac)
-----------------------------
1. Copy Find-0.18.16.zip to the iMac and double-click it to unzip. You get a folder named "Find".
   (Copy the .zip itself, not the loose files: the zip keeps line endings and permissions intact.)
2. Open Terminal and type:   cd
   then a space, then drag the "Find" folder onto the Terminal window, then press Return.
3. Type:   bash build.sh
   and press Return. It takes about one to three minutes.
4. When it says DONE, open Find.dmg (in the Find folder) and drag Find into Applications.

The build also runs Find's Safety Self-Check, Search Self-Test, Index Self-Test and Photo Metadata
Self-Test on the iMac. If a safety, search or index check fails, the build stops and no disk image is
made. If only photo metadata details fail, the build finishes with warning W-PHOTO-1 (send me the log).

IF THE BUILD FAILS
------------------
build.sh writes build-log.txt and copies it to the clipboard automatically.
Paste it into AutoType and type it into Notepad on the Windows machine, save as .txt, upload it.
The log is plain ASCII, one fact per line, every line numbered (B0001, B0002, ...), with the
errors listed first. Failure codes:
  E-BUILD-0  Xcode tools not found          E-BUILD-5  code signing failed
  E-BUILD-1  safety guard tripped           E-BUILD-6  disk image failed (app in build/ still ok)
  E-BUILD-2  Swift compile error            E-BUILD-7  built app did not start
  E-BUILD-3  Info.plist copy failed         E-BUILD-8  Safety Self-Check failed
  E-BUILD-4  Swift libraries not embedded   E-BUILD-9  Search Self-Test failed
                                            E-BUILD-10 Index Self-Test failed
                                            E-BUILD-11 a file changed while its metadata
                                                       was read (do not use the build)
  W-PHOTO-1  warning only: some photo metadata details could not be read back
  W-EXIF-1   warning only: ExifTool could not be bundled (inspector shows what macOS reads)

Codes in the log and in Settings reports (Find itself, not the build):
  E-GUARD-1   refused to remove something outside Find's own folders (nothing was removed)
  E-GUARD-2   refused to remove a previous version that isn't one of Find's temporary names
  E-MAINT-1   clean-up refused a path that is not one of Find's stores (nothing was removed)
  E-MAINT-2   an index file could not be deleted      E-MAINT-3  a cache file could not be removed
  E-RECOVER-1 a note line that doesn't look like Find's was ignored (nothing touched)
  E-RECOVER-2 an interrupted rename could not be put back (tried again at the next start)
  E-RECOVER-3 an unfinished copy could not be moved to the Trash (tried again at the next start)

ON THE MACBOOK PRO (Tahoe)
--------------------------
Use the Find.dmg built on the iMac (the MacBook has no Xcode). The first time, use
System Settings > Privacy & Security > "Open Anyway". For complete access to protected folders
(Mail, Safari data, etc.) on Tahoe, Find will later need Full Disk Access; Phase 1 simply reports
folders it can't read.


FILE SAFETY (how Find protects your files)
------------------------------------------
- "Move to Trash" uses the macOS Trash. On a drive or share that has no Trash (most shared
  volumes), Find does what Finder does (0.18.4): it asks "delete immediately? You can't undo this",
  naming the items, with Cancel as the main button - nothing is deleted unless you choose Delete.
  File > Delete Immediately... (Option-Cmd-Backspace; Option in the right-click menu) does the same
  anywhere. Never allowed: the top of a disk, a whole disk or share, your home folder and its main
  folders, and system folders.
- Ratings and metadata (0.12, settings 0.18.5 in Settings > Photography): Find writes a NEW version
  of the file under a hidden name beside it (or changes a separate working copy, in the safest
  mode), reads it back and checks every value as asked - and, unless you chose the fastest mode,
  that the picture data is bit-for-bit identical to the original's - and only then puts it in the
  original's place and removes the previous version, whose old values are kept for Edit > Undo.
  Where (0.18.6, all on by default): 1 the RAW's .xmp sidecar (an existing one is always kept up to
  date), 2 the XMP inside RAW files, 3 the IPTC inside every picture that holds it; JPEG/TIFF always
  get their XMP inside. A RAW rewritten inside has its previous version go to the Trash as
  "NAME (before metadata edit).NEF".
- Nothing is ever overwritten. Renames and moves use an atomic "fail if the name exists" rename.
  A name clash always asks: Keep Both, Skip, Replace (existing item goes to the Trash first), Stop.
- Copies are written under a hidden temporary name, checked (every file's size, every folder's
  contents), then renamed into place.
- Moving between drives = copy, verify, then the originals go to the Trash.
- Rename, New Folder, Move to Trash, Move, Copy and Duplicate can all be undone (Cmd-Z).
- Find writes no .DS_Store or any other file into your folders. The only things it puts there
  are hidden temporary names while it works (".find-partial-..." during a copy or save,
  ".find-rename-..." during a batch rename). Each is noted before it exists; if Find is stopped
  half way (crash, Force Quit, power cut), the next start gives renamed items their names back
  and moves unfinished copies to the Trash - never deletes anything - and tells you.
- Its own files live only in:
    ~/Library/Application Support/Find   (themes, search indexes, operation notes, clean-up record)
    ~/Library/Caches/Find                (saved previews, temporary files, self-test folders)
    ~/Library/Logs/Find                  (logs and reports)
  Clean-up (Settings > Storage & Maintenance) only ever removes from these, and a build-time
  guard makes sure only three source files can change anything on disk.
- Help > Run Safety Self-Check runs 57 checks of these rules on your Mac using test files only.
  Help > Run Search Self-Test checks search results against a folder with known contents.
  Help > Run Index Self-Test checks indexed searches always equal direct searches.
  Help > Run Photo Metadata Self-Test reads a test JPEG with known camera values and checks that
  reading (by macOS and by the bundled ExifTool) leaves the file byte-for-byte unchanged.
- The inspector, Quick Look and ExifTool reading only ever read files. Find writes into photos
  and XMP sidecars only when you rate, edit metadata or use Find and Replace on metadata (see above).
- Saved servers (0.13): server passwords are kept in the macOS Keychain, as Finder keeps them
  (Keychain Access shows them as internet passwords). Removing a saved server never touches the
  server or its files. Window positions are kept in Application Support/Find/session.json.

NEW IN 0.4.1
------------
- Fixed: on network shares, making a new folder (or other changes) could show "The folder
  ... was moved or deleted" and jump to the parent, though nothing had happened. Shares send
  macOS "deleted/renamed" signals for ordinary changes, and Find believed them. Nothing on disk
  was affected; Find only navigated away. Now each signal is checked on the disk: Find leaves
  a folder only if it is missing twice, a second apart. If the share can't be reached, Find
  stays and shows "Can't open this folder" instead. A folder that sends 3 false signals in
  10 seconds stops being watched; use View > Refresh (Cmd-R) to update it.

NEW IN 0.4.0
------------
- "Name is similar to (allows typos)": finds near matches. Case, accents and separators are
  ignored; words can be in any order; each word may have a few mistakes depending on its
  length (1-3 letters: none, 4-6: 1, 7-10: 2, longer: 3). A mistake is a wrong, missing or
  extra letter, or two neighbouring letters swapped. A Match column shows how close each is.
- Search indexes (Phase 2b), optional, for local folders you choose (Settings > Search Index).
  Each search checks every indexed folder's change stamp and re-reads only changed folders,
  then re-checks every match on the disk, so results are always the same as a direct search.
  No background process: the index is checked and updated only when you search.
  Size/date searches, network locations, and "Use index" unticked always search directly.
  The search details always say which method was used. Indexes hold names, sizes and dates
  only (never contents) in ~/Library/Application Support/Find/Indexes.

SEARCH
------
Cmd-F (or click the search field at the top right), type, press Return.
The search bar shows WHERE you are searching (always visible) and lets you pick:
  This folder only / This folder and subfolders / Selected folders and subfolders /
  This drive / All local drives / This network location / All locations
Name contains / is / begins with / ends with / wildcard (* ?) / regular expression,
Match case, Include System Files (off by default), Hidden files.
"More" adds: files or folders, extensions (nef, dng), size range in MB, modified after/before,
folder name, inside packages, follow folder links, match all / any.
Results appear as they are found; sort them while the search runs. Stop at any time.
Every search ends with an honest status:
  "Complete" only when every folder in scope was read.
  "INCOMPLETE" lists exactly which folders could not be searched and why (permission,
  missing, disconnected). Folders skipped because of a setting (hidden, system, packages,
  links, other drives) are counted, with examples, under "Search details".
Double-click a result to open it; right-click > Show in Enclosing Folder. Escape leaves search.
The optional index (Phase 2b) comes next, once direct search is confirmed on your Mac.
